# Ai-learning-platform — audit, 2026-09-17

What the repo actually is: a 6-page static site (vanilla HTML/CSS/JS, no framework
at runtime) generated by Google AI Studio, carrying a 17-track / 313-task
curriculum, a 26-entry language evolution chain, and 432 syntax rows across 21
languages. Two commits, clean tree, no tests, no build ever run.

---

## 1. The headline problem: 78% of lessons are a template

`lessons-data.js` is 177 KB, but coverage of the 313 tasks breaks down as:

| lesson source | tasks | what the reader gets |
|---|---|---|
| handcrafted (`curatedLessons`) | 44 | real history, real numbers, real code |
| language-chain generator | 26 | decent — built from real per-language fields |
| `generateFallbackLesson()` | **243** | **the same six paragraphs with the title swapped in** |

The fallback reads:

> "In the evolution of software systems, `${task.text}` represents a critical
> engineering threshold within `${track.name}`…"

…and its Beat 4 asks the identical question for all 243: *"How do you identify and
mitigate the primary failure mode when implementing X in a production distributed
environment?"* — asked about "What a file is" and about "Transformers" alike.
Its `blueprint` emits a stub function with three comments and no body.

**Why this is worse than an empty page:** an empty page tells the reader to go
find the answer. A confident-sounding paragraph that contains no fact teaches
them the shape of an explanation without the substance, and it is indistinguishable
from the 44 real lessons until you read it. Per track: B 37, E 26, L 23, O 19, M 14,
N 14, K 14, J 13, G 11, D 10, F 10, P 10, I 10, H 9, C 8, A 8, 0 7.

## 2. Bug: 12 handcrafted lessons are silently discarded

`curatedLessons` is one object literal with **56 entries but only 44 unique keys**.
Duplicated keys — `K.2 K.6 K.11 K.13 L.6 L.9 L.12 J.1 E.4 F.8 A.2 B.32` — are
legal JS; the later value just wins. No error, no warning.

Two of the losses are real regressions, not identical twins:
- **A.2** — the discarded copy is 3081 B, the surviving one 2951 B.
- **J.1** — the discarded copy is 2993 B, the surviving 3176 B (this one improved).
- **B.32** — surviving copy is 9970 B vs 3237 B, the richest lesson in the file.

So the file was written, then partly re-written, and the second pass was appended
instead of merged. ~37 KB of the 177 KB file is unreachable.

**Why it happened:** nothing validates the data. No schema, no test, no lint rule
(`no-dupe-keys` would have caught this in one second).

## 3. Structure: two apps in one folder, one of them dead

- `src/App.tsx` renders `<div></div>`. `src/main.tsx` mounts it. Nothing links to it.
- `package.json` is named `"react-example"` and depends on React 19, react-dom,
  lucide-react, motion, express, dotenv, `@google/genai` — **zero of which appear
  in any shipped file.** Grep for `genai|express|API_KEY` across the site: no hits.
- `metadata.json` declares `MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API`. There is no
  server. `.env.example` asks for `GEMINI_API_KEY` that nothing reads.
- `vite.config.ts` lists 5 build inputs: index, track, languages, words, progress.
  **`lesson.html` is not among them** — the page every task links to is excluded
  from the production build. `npm run build` ships a site whose lesson links 404.

**Why:** the AI Studio React template was kept as a shell, the real site was
written as multi-page vanilla JS inside it, and the two were never reconciled.

## 4. Numbers that do not match

- `metadata.json` and the homepage hero both say **330 tasks**. The data has **313**.
- The hero hedges with "roughly", which reads as deliberate, but the count is
  computed live on the same page — so the page contradicts itself.

## 5. Language chain: 5 dead ends and 6 backward jumps

`leadsTo` is supposed to make one story. It doesn't close:
- Chain ends at **C.23 CUDA, C.24 HTML/CSS, C.25 Bash, C.26 regex** — four terminal nodes.
- Nothing points *to* **C.8 Smalltalk, C.14 PHP, C.24, C.25, C.26** — five orphans.
  Smalltalk being an orphan is the notable one: it is the node that should feed C++.
- Listed order goes backward in time at C.4 (LISP 1958 after COBOL 1959), C.16
  (Erlang 1986 after Ruby 1995), C.21, C.22 (SQL 1974 after Rust 2015), C.24, C.25, C.26.

The last five are a *different category* — SQL, CUDA, HTML/CSS, Bash, regex are not
links in the general-purpose chain, they are parallel notations. Presenting them in
one numbered timeline is what makes the dates look wrong.

## 6. Syntax tables: no storyline, and 4 chain languages have no table

- 21 tables × `[syntax, plain meaning, why it matters]` rows. The rows are good.
- But they are a **reference list, not a story**: nothing says why the language's
  syntax looks the way it does, what problem each construct answers, or in what
  order a reader should meet them. A table sorted by topic is a dictionary. The
  site's whole thesis (Four Beats) is that things exist because something broke.
  The tables abandon that thesis.
- **Fortran, LISP, Smalltalk, Perl** are in the chain with no syntax table at all.
- Coverage is lopsided: JavaScript 36 rows, Elixir 11, Kotlin 12, Swift 12.
